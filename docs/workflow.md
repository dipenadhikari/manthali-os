# Product Workflow

## User journey

```text
Open ManthaliOS
      ↓
Search or browse a service
      ↓
Open service page
      ↓
Understand eligibility and requirements
      ↓
Review official source
      ↓
Create personal checklist
      ↓
Complete preparation steps
      ↓
Use official channel to take action
```

## Admin journey

```text
Admin creates service
      ↓
Adds structured requirements
      ↓
Adds official source
      ↓
Reviews information
      ↓
Marks source as verified
      ↓
Publishes service
      ↓
Future review / re-verification
```

## AI boundary

```text
Verified service data
        ↓
     AI layer
        ↓
Plain-language explanation
        ↓
User
        ↓
Official source for authority
```

The AI layer should not invent missing requirements, dates, fees, eligibility rules, or official decisions.

## Verification model

A service should have enough provenance to answer:

- what source supports this information?
- who verified it?
- when was it verified?
- is it currently published?

A future implementation can add source snapshots and change history as the product matures.
